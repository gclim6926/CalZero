# Pre-단계. 초기 미팅 / 도입 검토(Initial Meeting & Feasibility Review)

> 로봇 도입 전 공급업체와 진행하는 사전 검토 단계입니다.
>
> 공급업체의 일반 현황과 납품 실적을 확인하고, 도입 대상 로봇 모델을 **QCD(품질·비용·납기)** 관점에서 평가합니다. 또한 실제 현장에서 수행할 태스크를 먼저 정의하고, 해당 로봇이 이를 수행할 수 있는지를 사전에 검토하는 것이 이 단계의 핵심입니다.

## Pre-1. 기본 정보(Basic Information)

공급업체 일반 현황 및 도입 모델의 비용(Cost)·납기(Delivery) 정보를 확인합니다.

| 항목                        | 설명                                                                                             | 제공 형태        |
| --------------------------- | ------------------------------------------------------------------------------------------------ | ---------------- |
| 공급업체 일반 현황          | 회사 규모, 설립 연도, 주요 고객사 및 시장 내 위치. 사업 안정성과 장기 지원 가능 여부 판단 기준   | 회사 소개서      |
| 수행 및 납품 이력           | 유사 업종·환경에서의 납품 사례 및 실제 운용 실적. 동일하거나 유사한 태스크에 대한 레퍼런스 확인 | 사례 문서 / 영상 |
| 로봇 모델 기본 정보         | 제조사명, 모델명, 라인업 구성 및 주요 사양 요약. 비교 검토 대상 모델 범위 확정                   | 제품 카탈로그    |
| 도입 비용(Cost)             | 로봇 본체 단가, 소프트웨어 라이선스 비용, 연간 유지보수 비용. 총소유비용(TCO) 산정 기준          | 견적서           |
| 납기 및 지원 조건(Delivery) | 납기 리드타임, 설치 지원 조건, 보증 기간, A/S 정책. 도입 일정 수립 및 운용 중단 리스크 판단 기준 | 계약 조건서      |

## Pre-4. 태스크 정의 및 수행 가능성 검토(Task Definition & Feasibility)

수행할 태스크를 먼저 명확히 정의한 후, 해당 로봇이 이를 실제로 수행할 수 있는지 검토합니다. 태스크가 구체적으로 정의되지 않으면 성능 수치 비교 자체가 의미를 잃습니다.
태스크 명세서: 도입 목적에 따라 수행할 태스크를 구체적으로 정의. 대상 물체 종류·크기·무게, 작업 환경 조건, 성공 기준(Success Criteria) 포함

| 항목                                                   | 설명                                                                                               |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| 태스크 수행 가능 여부 판단                             | 태스크 명세서 기반 성공/실패에 대한 논의                                                           |
| 피킹 정확도(Pick Accuracy)                             | 크기/모양/무게 조건별 pick accuracy(%). 정의된 태스크 기준으로 수행 가능 여부 판단                 |
| 새 환경 적응 시간                                      | 사전 맵 없이 새 환경 레이아웃에 적응하는 데 걸리는 시간. zero-shot vs fine-tune 시나리오 각각 확인 |
| 동적 장애물 회피 반응 지연(Obstacle Avoidance Latency) | 이동 물체·작업자 혼재 환경에서 감지 → 회피 완료까지 지연 시간(ms). 혼재 작업 안전성 판단 기준    |
| 비정상 상황 자율 복구(Autonomous Recovery) 범위        | 파지 실패/낙하 등 이상 상황에서 인간 개입 없이 자율 복구되는 시나리오 범위 및 성공률               |
| 구현 최고 수준 태스크                                  | 현재까지 구현한 가장 복잡한 태스크 데모. 기술 성숙도 및 정의된 태스크와의 갭 판단                  |

# 단계 1. 로봇 도입 / 등록(Robot On-boarding & Registration)

제조사로부터 사전에 확보한 하드웨어 사양을 기반으로 데이터를 등록합니다. 이 등록 데이터는 이후 모든 캘리브레이션·운용·이력 관리의 기준점(baseline)이 됩니다.

단순한 장치 등록을 넘어, 복수 로봇을 운용하거나 장기적으로 개체별 캘리브레이션 이력을 비교·관리하기 위한 데이터 구조를 이 단계에서 만들어두는 것이 핵심입니다. 여기서 정확히 입력된 파라미터가 캘리브레이션 정밀도와 시뮬레이션 정합성의 토대가 됩니다.

## 1-1. 관절 파라미터(Joint Parameters)

CalZero가 캘리브레이션 구조를 생성하는 핵심 데이터입니다. 실제 제조사가 제공한 기본값과 실측 데이터를 비교하기 위한 기준으로 사용됩니다.
제조사가 정확한 Specification과 함께 기본값을 제공하고, 실제 캘리브레이션 후 CalZero 실측값으로 업데이트됩니다.

| 항목                                            | 설명                                                                                                       |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| 캘리브레이션 및 자체 동적 검증 방법             | 로봇을 사용하기 전, 자체 보정 및 기본 동작을 점검하는 방법                                                |
| 관절 구성(Joint Configuration)                  | 자유도(DOF), 관절 목록/이름/순서, 관절 타입(Revolute/Prismatic). CalZero UI 및 DB 구조의 기본 뼈대         |
| 액추에이터 정보(Actuator Info)                  | 관절별 모터 모델명, 액추에이터 ID, 엔코더 해상도(Encoder Resolution). 통신 설정 및 각도↔틱 변환 계산 기준 |
| 캘리브레이션 및 검증 방법                       | 물리적 로봇을 사용하기 전, 기본 점검 방법                                                                  |
| 이동 범위(range_min / range_max) — 물리 한계   | 관절의 물리적 최소/최대 이동 범위 (encoder tick). 소프트 리밋(Soft Limit) 설정 기준                        |
| 최대 속도(Max Velocity) / 최대 토크(Max Torque) | 관절별 속도 및 토크 한계. 과속/과부하 보호 설정 기준                                                       |
| 강성/감쇠(Stiffness / Damping)                  | 액추에이터별 강성/감쇠 파라미터. URDF에는 포함되지 않으나 시뮬레이터 actuator 모델링에 필수                |

# 단계 2. 입고 및 테스트(Receiving & Initial Testing)

> 로봇이 현장에 실제로 도착한 후, 본격적인 운용을 시작하기 전에 수행하는 초기 검증 단계입니다.
>
> 이 단계는 크게 세 가지 목적을 가집니다. 첫째, 통신 연결·관절 상태·안전 기능 등 하드웨어가 정상적으로 동작하는지 확인합니다. 둘째, CalZero를 통해 개체 고유의 캘리브레이션 값을 실측하여 저장합니다. 특히 캘리브레이션 실측값은 제조사 기본값과 반드시 비교 검토해야 합니다.

## 2-1. 초기 통신 및 하드웨어 확인(Initial Communication & HW Verification)

# Post 단계. Sim-to-Real 검증(Sim-to-Real Validation)

> 시뮬레이터에서 학습한 AI 정책(Policy)이 실제 로봇에서 의도한 대로 동작하는지를 체계적으로 검증하는 단계입니다.
>
> 시뮬레이터는 현실을 완벽히 재현할 수 없기 때문에, 가상 환경(Sim)과 현실(Real) 사이에는 반드시 차이(Domain Gap)가 존재합니다. 이 단계에서는 시뮬레이터 모델 정합성 → 운동학/역학 매칭 → 센서 데이터 매칭 → 정책 전이(Policy Transfer) 순서로 gap을 계층적으로 측정하고, 도메인 랜덤화(Domain Randomization) 범위와 파인튜닝(Fine-tuning) 전략을 데이터 기반으로 조정합니다.
>
> 이 단계에서 충분한 검증이 이루어져야 실제 현장 배포 시 예상치 못한 실패를 예방할 수 있습니다. 발견된 gap이 클수록, 다음 학습 사이클의 합성 데이터 설정이나 실로봇 데이터 수집 전략을 재검토해야 합니다.

## Post-1. 시뮬레이터 모델 정합성(Simulation Model Fidelity)

업체 제공 모델 파일이 실제 로봇을 정확히 표현하는지 기본 수치부터 확인합니다.

| 항목                                           | 설명                                                                                                                                          | 검증 방법                                                             | 판단 기준                                   |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- | ------------------------------------------- |
| 관절 범위(Joint Limit) 일치 여부               | 모델 파일의 joint limit(min/max)과 CalZero 실측 range_min/range_max 비교. 차이가 크면 Sim에서 실제로 불가능한 자세가 학습될 수 있음           | CalZero 실측값과 모델 파일 수치 대조                                  | 오차 ±5% 이내 권장                         |
| 링크 길이 / 질량(Link Length / Mass) 정확도    | 모델 파일의 링크 길이와 질량(mass) 값이 실제 로봇과 일치하는지. 값이 틀리면 Sim의 end-effector 도달 위치가 실제와 달라짐                      | 줄자/저울 실측 후 모델 파일 수치 대조                                 | 링크 길이 오차 ±2mm 이내 권장              |
| 홈 포지션(Zero Pose) 일치 여부                 | Sim에서 모든 관절값 0일 때의 자세가 실제 로봇 홈 포지션과 동일한지. 불일치 시 모든 좌표 계산의 기준이 틀어짐                                  | Sim 0-pose 시각화 vs 실로봇 홈 포지션 사진 비교                       | 육안 일치 + end-effector 위치 오차 ±5mm    |
| 강성/감쇠(Stiffness / Damping) 파라미터 유효성 | 시뮬레이터에 설정한 actuator stiffness/damping 값이 실제 관절 응답과 유사한지. 값이 안 맞으면 Sim 동작이 실로봇보다 딱딱하거나 흐물거림       | 동일 step 명령 인가 후 관절 응답 곡선 비교                            | 응답 곡선 형태 유사 여부 육안 확인          |
| 충돌 메시(Collision Mesh) 정확도               | 시뮬레이터 모델의 collision geometry가 실제 로봇 외형과 일치하는지. 틀리면 Sim에서 충돌하지 않아야 할 자세가 충돌로 처리되거나 반대 상황 발생 | Sim에서 self-collision 테스트 자세 재현 후 실로봇 동일 자세 실행 비교 | Self-collision false positive/negative 없음 |

## Post-2. 운동학/역학 매칭(Kinematics & Dynamics Matching)

같은 명령을 주었을 때 Sim과 Real의 동작이 얼마나 일치하는지 정량 측정합니다.

| 항목                                         | 설명                                                                                                                        | 검증 방법                                              | 판단 기준                                                                |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------ |
| 순운동학(Forward Kinematics) 오차            | 동일한 joint angle 명령 시 Sim과 Real의 end-effector 위치 차이. FK 오차가 크면 Sim에서 학습한 도달 동작이 실로봇에서 빗나감 | 5~10개 기준 자세에서 end-effector 3D 위치 측정 후 비교 | 위치 오차 ±5mm, 자세 오차 ±2° 이내 권장                               |
| 속도/가속도(Velocity/Acceleration) 응답 일치 | 동일한 velocity 명령에 대한 실제 관절 속도 프로파일 비교. Sim이 너무 빠르거나 느리면 timing 기반 policy가 실패함            | 동일 velocity 명령 후 encoder 데이터 시계열 비교       | 속도 프로파일 형태 유사, 최종값 오차 ±10%                               |
| 토크 / 중력 보상(Gravity Compensation) 동작  | 동일 자세에서 Sim과 Real의 관절 토크 값 비교. 중력 보상이 Sim과 다르면 실로봇이 자세를 유지 못하거나 과토크 발생            | 정적 자세에서 각 관절 필요 토크 측정 후 Sim 수치 대조  | 토크 오차 ±15% 이내 권장                                                |
| 마찰 / 백래시(Friction / Backlash) 특성      | Sim에는 없거나 단순화된 마찰/백래시가 실로봇에서 얼마나 나타나는지. 무시하면 정밀 제어 태스크에서 반복 오차 발생            | 저속 왕복 동작에서 encoder 편차 측정                   | 백래시 크기 기록 후 도메인 랜덤화(Domain Randomization) 범위 설정에 반영 |

## Post-3. 센서 데이터 매칭(Sensor Data Validation)

Sim의 가상 센서 출력과 실제 센서 출력이 일치하는지 확인합니다. 불일치 시 관측 공간(Observation Space)이 달라져 policy 실패로 이어집니다.

| 항목                                              | 설명                                                                                                                                             | 검증 방법                                                   | 판단 기준                                                              |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------- | ---------------------------------------------------------------------- |
| 카메라 내부 파라미터(Camera Intrinsics) 일치      | Sim 렌더 카메라의 fx/fy/cx/cy와 CalZero로 측정한 실제 카메라 파라미터 비교. 불일치 시 Sim 이미지 기반으로 학습한 policy가 실제 이미지에서 오인식 | Sim 카메라 파라미터 vs CalZero 실측값 대조                  | 초점거리 오차 ±5% 이내                                                |
| 이미지 도메인 갭(Image Domain Gap)                | Sim 렌더링 이미지와 실제 카메라 이미지의 색상/밝기/텍스처 차이. 시각 기반 policy의 가장 큰 Sim-to-Real 실패 원인                                 | 동일 장면을 Sim과 Real에서 촬영 후 SSIM/도메인 갭 육안 확인 | 심각한 질감/조명 차이 여부 확인, domain randomization 범위 결정에 반영 |
| 힘/토크 센서(F/T Sensor) 제로 오프셋(Zero Offset) | 실로봇 F/T 센서의 zero drift 여부 확인. Sim은 이상적 0값이지만 실제 센서는 온도/자세에 따라 drift 발생                                           | 동일 자세에서 F/T 센서 무부하 값 반복 측정                  | Zero offset 크기 기록 후 보정 처리 여부 결정                           |
| 관절 엔코더(Joint Encoder) 노이즈 수준            | 실로봇 encoder 신호의 노이즈 크기. Sim은 노이즈 없이 깨끗한 값을 반환하므로 실로봇에서 policy 입력이 흔들릴 수 있음                              | 정지 상태에서 encoder raw 값 100회 측정 후 표준편차 확인    | 표준편차 기록 후 Sim domain randomization 관절 노이즈 범위에 반영      |

## Post-4. 정책 전이 검증(Sim-to-Real Policy Transfer)

Sim에서 학습한 policy를 실로봇에 배포했을 때의 성능을 측정하고 개선 방향을 결정합니다.

| 항목                                            | 설명                                                                                                    | 검증 방법                                                 | 판단 기준                                                                          |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 제로샷 전이(Zero-shot Transfer) 성공률          | fine-tune 없이 Sim-only policy를 실로봇에 배포했을 때 태스크 성공률. 베이스라인 gap 측정용              | 동일 태스크 20회 반복 실행 후 성공률 기록                 | 성공률이 기준 이하면 domain randomization 강화 또는 fine-tune 데이터 수집으로 전환 |
| 도메인 랜덤화(Domain Randomization) 설정 적정성 | Sim 학습 시 사용한 DR 범위(조명/질감/관절 노이즈/페이로드 등)가 실제 환경 변동 범위를 커버하는지        | 3-1~3-3 측정값을 DR 설정과 대조                           | 실측 편차가 DR 범위 내에 포함되는지 확인, 미포함 항목은 DR 범위 재조정             |
| 파인튜닝(Fine-tuning) 후 성능 향상              | 실로봇 데모 데이터로 fine-tune 후 성공률 변화. 투입 에피소드 수 대비 성능 향상 곡선 기록                | fine-tune 전/후 동일 태스크 20회 반복 비교                | 에피소드 수 대비 성능 수렴 여부 확인                                               |
| 데이터 포맷(Data Format) 호환성                 | Sim 합성 데이터와 실로봇 수집 데이터의 포맷(관절명/차원/단위)이 학습 프레임워크에서 동일하게 처리되는지 | 두 데이터 소스를 동시에 로드하여 배치 단위 shape/key 확인 | 포맷 불일치 없이 동일 dataloader 처리 가능 여부                                    |
| 이상 동작 자율 복구(Autonomous Recovery) 확인   | Sim에서 학습된 recovery policy가 실로봇에서도 동작하는지. 파지 실패/낙하 상황 재현 후 복구 성공 여부    | 의도적 실패 상황 5회 연출 후 복구 성공률 기록             | 복구 성공률 및 복구 소요 시간 기록                                                 |
